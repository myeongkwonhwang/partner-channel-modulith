# 하루 마무리 (End of Day)

오늘 대화에서 한 작업과 결정을 **두 곳에 기록**한다. 두 기록은 역할이 다르므로 한쪽만 하면 미완.

| 기록 | 역할 | 위치 |
|------|------|------|
| 메모리 | 미래 대화에서 적용될 결정 / 협업 스타일 / 도메인 사실 | `~/.claude/projects/-Users-mk-repository-mk-partner-channel-modulith/memory/` |
| worklog | 오늘 날짜의 작업 / 결정 사실 (history) | `docs/worklog/YYYY-MM-DD.md` |

## 단계

### Step 1 — 오늘 한 일 식별

대화 컨텍스트에서 다음을 추출:

- **코드 변경** — 어떤 모듈 / 어떤 의도 / 어떤 산출물
- **결정** — 구조 / 명명 / 정책. 합의 흐름 (선택지 + 사용자 선택) 포함
- **검증 결과** — 빌드 / 테스트 통과 여부
- **미루어진 것** — 다음 라운드 후보

### Step 2 — 메모리 저장

CLAUDE.md 의 auto memory 정책 따름. 한 라운드에 보통 1 ~ 3 파일:

- **project** — 이번 라운드의 결정 + 결과 1 파일 (예: `project_pcm_<round-name>.md`)
- **feedback** — 사용자가 명시적으로 표현했거나 반복된 선택 패턴 (예: 추상 베이스 < 도메인별 분리)
- **user** — 사용자 역할 / 지식 / 선호 단서 (얻은 게 있을 때만)
- **reference** — 외부 시스템 / 자원 (얻은 게 있을 때만)

저장 후 `MEMORY.md` 인덱스에 한 줄 추가. 이미 본 대화에서 일부 메모리가 저장돼 있을 수 있으니 시작 전 `MEMORY.md` 확인.

### Step 3 — worklog 작성

**위치**: `docs/worklog/YYYY-MM-DD.md` (YYYY-MM-DD = 시스템 컨텍스트의 `currentDate`).

#### 정책 (이 프로젝트 컨벤션 — 반드시 지킬 것)

- **워딩 / 산문 / 감상 제외**. 작업 / 결정 사실만.
- **메모리 참조 (`[[...]]`) 제외**. worklog 는 독립적 history — 메모리 시스템과 분리.
- 이미 오늘 자 worklog 가 있으면 **append** (이어쓰기, 작업 단위 번호 이어감). 없으면 신규.
- 작업 단위는 ①②③ 환원숫자. 다음 날 worklog 와 일관.

#### 형식

```markdown
# YYYY-MM-DD Worklog

## Summary
- 한 줄 요약 3 ~ 5 개

---

## 작업 단위 (시간순)

### ① <작업 단위 제목>
- 무엇 / 어디 / 어떻게 (불릿)
- 결과 / 산출물

### ② ...

---

## 합의된 정책 (이번 세션 신규)

| 정책 | 결정 |
|---|---|
| ... | ... |

---

## git
- stage / commit / 미실행 등 사실

---

## 다음 진입점 후보

| 후보 | 설명 |
|---|---|
| ... | ... |
```

각 섹션은 해당 내용이 있을 때만 작성 (예: 합의된 정책이 없으면 섹션 자체 생략).

### Step 4 — 보고

사용자에게 짧게:

- 저장된 메모리 파일 목록 (신규 vs 이미 저장됨)
- 작성된 worklog 경로 (신규 vs append)
- 한 줄 요약

## 주의

- worklog 와 메모리는 **다른 형식 / 다른 정책**. 메모리는 `[[...]]` 링크 / Why / How to apply 등 구조 있지만 worklog 는 사실 위주 평문.
- 사용자가 "메모리만" 또는 "worklog 만" 명시하면 그쪽만 수행. 그 외에는 두 단계 모두 수행.
- git 명령 (`git status`, `git diff --stat`) 으로 오늘 stage / commit 상태 확인 후 git 섹션 작성.
